# Обоснование

## Выбор платформы Yandex Cloud
- Оборудование локализовано в России. Российское законодательство требует хранения медицинских и финансовых данных на территории РФ.
- Географическое покрытие - наличие нескольких зон доступности в ru-central1 позволяет реализовать отказоустойчивость
- Интеграция с экосистемой: Поддержка современных технологий (Kafka, Managed Databases) соответствует требованиям Data Mesh

## Infrastructure as Code (IaC) подход
- Конфигурации хранятся в Git, что позволяет отслеживать изменения и выполнять rollback
- Несколько инженеров могут совместно работать над инфраструктурой
- Код самодокументирует архитектуру

## NAT 
- Внутренние сервисы недоступны из интернета
- Один внешний IP вместо выделения каждому инстансу
- Централизованное управление исходящим трафиком

## Ресурсы

| ----------------- | ----------------------- | ------------------------------------------------------------------------------------------------------- |
| Медицинский домен | 8 vCPU, 16GB RAM        | Обработка медицинских данных требует значительных вычислительных ресурсов для трансформаций и валидации |
| Финансовый домен  | 8 vCPU, 16GB RAM        | Финансовые расчеты и обработка транзакций требуют высокой производительности CPU                        |

| BI портал         | 8 vCPU, 16GB RAM        | Power BI и аналитические запросы требуют ресурсов для быстрой обработки                                 |
| Data Processing   | 16 vCPU, 32GB RAM       | Apache Spark и Airflow требуют значительных ресурсов для параллельной обработки данных                  |
